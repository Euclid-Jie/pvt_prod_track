# Web 服务访问控制

`pvt_prod_track_web.exe` 默认只监听 `127.0.0.1:5003`。公网访问通过服务器 Nginx 进入现有 FRP TCP 通道，桌面版 `pvt_prod_track.exe` 不启用这套访问控制。

## 首次启动

1. 在终端中启动 `pvt_prod_track_web.exe`。
2. 启动窗口会打印一次性管理员设置口令。
3. 在服务所在电脑打开 `http://127.0.0.1:5003/admin/setup`。
4. 输入一次性口令并创建至少 12 个字符的管理密码。

管理入口只接受本机直连，并且仍要求管理密码。管理员登录有效期为 8 小时，服务重启后需要重新登录。

如果忘记管理密码，停止服务后运行：

```powershell
.\pvt_prod_track_web.exe -reset-admin
```

该参数只重置管理密码并生成新的一次性口令，不会删除申请或白名单。

## 公网代理与 HTTPS

当前请求路径为：

```text
访客 -> Nginx :80/:443 -> FRPS 127.0.0.1:25003 -> FRPC -> 本机 127.0.0.1:5003
```

### 端口归属

| 端口 | 归属进程 | 用途 | 是否进入 FRP |
| --- | --- | --- | --- |
| 公网 `80` | Nginx | 周报正式入口 | 是，Nginx 再转发到内部 `25003` |
| 公网 `15003` | Nginx | 旧地址迁移引导页 | 否，只返回静态引导页 |
| 服务器 `25003` | FRPS | 周报的内部 FRP TCP 端口 | 是，不对公网开放 |
| 本机 `5003` | `pvt_prod_track_web.exe` | 周报应用监听端口 | FRPC 最终转发目标 |

公网 `15003` 已完全由 Nginx 接管。访问该端口不会连接 FRPS、FRPC 或周报应用，也不能绕过访问白名单；只有用户进入正式地址后，请求才会从 Nginx 的 `80` 端口经内部 `25003` 进入 FRP。

Nginx 使用 `docs/nginx-pvt-prod-track.conf`，覆盖而不是沿用访客传入的真实 IP 请求头：

- `X-Forwarded-For: $remote_addr`
- `X-Forwarded-Proto: $scheme`

周报的 FRP 内部端口已迁移到 25003，且不应对公网开放。云安全组开放 80/443 作为正式入口；旧端口 15003 由 Nginx 提供迁移引导页，不再直接连接 FRPS。Nginx 从服务器回环地址访问 25003，不受公网入站规则影响。

当前 HTTP 入口可用于验证，正式使用应配置域名和 HTTPS。HTTPS 生效后，`X-Forwarded-Proto` 会使设备 Cookie 自动带上 `Secure` 属性。

不要把 5003 端口直接开放到公网。确需覆盖监听地址时可使用 `-listen`，例如 `-listen 0.0.0.0:5003`，但这会扩大可直连范围。

## 审批流程

- 未获授权的访客会进入 `/access`，提交称呼、可选联系方式和留言。
- 管理员在本机打开 `http://127.0.0.1:5003/admin` 查看申请。
- 申请记录可按姓名或团队名即时查询，并可与审批状态筛选同时使用。
- “批准”默认只批准当前浏览器设备；也可以改为批准当前 IP，或同时批准两者。
- 设备与 IP 任一有效白名单命中即放行。
- 撤销白名单立即生效，原审批记录仍保留；访客可以重新提交申请。

设备编号是服务端签发给浏览器的随机凭证。清除 Cookie、使用无痕模式或更换浏览器后会得到新的设备编号。

## 本地文件

申请、白名单和管理密码哈希保存在运行数据目录的 `access_control.json`。文件采用临时文件替换写入；读取或解析失败时服务拒绝访问，不会绕过白名单。

不要把 `access_control.json` 上传、提交到版本库或发送给他人。
