# Web 服务访问控制

Web 服务默认只监听 `127.0.0.1:5003`。生产环境由 Ubuntu 服务器上的 Nginx 反向代理到该回环端口，桌面版 `pvt_prod_track.exe` 不启用这套访问控制。

## 首次启动

1. 在终端中启动 `pvt_prod_track_web.exe`。
2. 启动窗口会打印一次性管理员设置口令。
3. 在服务所在电脑打开 `http://127.0.0.1:5003/admin/setup`。
4. 输入一次性口令并创建至少 12 个字符的管理密码。

管理入口只接受本机直连，并且仍要求管理密码。管理员登录有效期为 8 小时，服务重启后需要重新登录。

如果忘记管理密码，停止服务后运行：

```powershell
.\pvt_prod_track_web.exe -reset-admin
```

该参数只重置管理密码并生成新的一次性口令，不会删除申请或白名单。

## 公网代理与 HTTPS

当前请求路径为：

```text
访客 -> Nginx :80/:443 -> Ubuntu 服务 127.0.0.1:5003
```

### 端口归属

| 端口 | 归属进程 | 用途 | 是否进入 FRP |
| --- | --- | --- | --- |
| 公网 `80` | Nginx | 周报正式入口 | 否，Nginx 转发到服务器回环 `5003` |
| 公网 `15003` | Nginx | 旧地址迁移引导页 | 否，只返回静态引导页 |
| 服务器 `5003` | `pvt_prod_track_web` | 周报应用监听端口 | 否，只绑定 `127.0.0.1` |

公网 `15003` 已完全由 Nginx 接管。访问该端口只返回静态迁移页，不会连接周报应用，也不能绕过访问白名单；正式请求由 Nginx 的 `80` 端口转发到服务器回环 `5003`。

Nginx 使用 `docs/nginx-pvt-prod-track.conf`，覆盖而不是沿用访客传入的真实 IP 请求头：

- `X-Forwarded-For: $remote_addr`
- `X-Forwarded-Proto: $scheme`

云安全组只需开放 80/443 作为正式入口；旧端口 15003 由 Nginx 提供迁移引导页。应用端口 5003 只绑定服务器回环地址，不加入公网安全组。

当前 HTTP 入口可用于验证，正式使用应配置域名和 HTTPS。HTTPS 生效后，`X-Forwarded-Proto` 会使设备 Cookie 自动带上 `Secure` 属性。

不要把 5003 端口直接开放到公网。确需覆盖监听地址时可使用 `-listen`，例如 `-listen 0.0.0.0:5003`，但这会扩大可直连范围。

## 审批流程

- 未获授权的访客会进入 `/access`，提交称呼、可选联系方式和留言。
- 管理员通过 SSH 隧道打开 `http://127.0.0.1:5503/admin` 查看申请，例如 `ssh -L 5503:127.0.0.1:5003 zeus`。
- “数据更新”只读写云端配置的 `last_day`，不会向浏览器返回数据库地址或凭据。新日期通过真实查询且存在可展示数据后才会生效；本地桌面版的日期设置不会同步到云端。
- “访问历史”记录最近 1000 次公网首页访问，展示时间、IP、设备编号、浏览器信息以及是否已获授权；同时按设备优先、IP 兜底关联白名单和来源申请，展示申请人姓名、联系方式与留言。静态资源和 API 请求不重复计数。
- 已获授权的用户可以在周报底部发布建议留言，公开名称取当前有效的设备白名单，设备未单独命名时再取 IP 白名单。公开内容不包含 IP、联系方式或设备标识。
- 管理页“建议留言”可以发布或覆盖一条管理员回复，也可以永久删除留言。回复和删除接口沿用管理入口的本机直连、登录会话和同源校验。
- 申请记录可按姓名或团队名即时查询，并可与审批状态筛选同时使用。
- “批准”默认只批准当前浏览器设备；也可以改为批准当前 IP，或同时批准两者。
- 设备与 IP 任一有效白名单命中即放行。
- 撤销白名单立即生效，原审批记录仍保留；访客可以重新提交申请。

设备编号是服务端签发给浏览器的随机凭证。清除 Cookie、使用无痕模式或更换浏览器后会得到新的设备编号。

## 本地文件

申请、白名单和管理密码哈希保存在运行数据目录的 `access_control.json`。建议留言及管理员回复单独保存在同目录的 `feedback.json`；每次写入采用临时文件替换，并将前一版保留为 `feedback.json.bak`。留言列表从内存分页读取，不进入产品数据查询或缓存路径。

不要把 `access_control.json`、`feedback.json` 或其备份上传、提交到版本库或发送给无关人员。

正式入口 `80` 的完整请求日志单独保存在 `/var/log/nginx/pvt-prod-track.access.log`。管理页访问历史用于快速查看首页访问，Nginx 日志用于请求级排查和审计。
